# 小G交互契约 · R1.2

2026-09-15。先完成 R1.1 七种空间分析方法对白的真实浏览器验收，再实现本次动作。最新用户修正：**Yes 点头；No 挥手，头部保持稳定。** 魔方仍独立运动，不需要托举或抓握。

## 直接体验

打开 prototype.html，移动鼠标观察眼神。在“任务进度”展开工作台，点击“演示成功流程”或“演示失败流程”。本地演示先显示进行中，900ms 后显示指定结果，不发送作业请求、不追加历史记录、不生成业务结果。

| 情况 | 小G反馈 |
|---|---|
| 当前任务首次进入 succeeded | 原模型 Yes 的头颈动画，约1.67秒，播放一次 |
| 当前任务首次进入 failed | 原模型 Wave 的右肩、手臂和手指动画，约1.83秒，播放一次；不加载 No 摇头轨道 |
| 首次读取历史终态、重复轮询 | 不播放结果动作 |
| 取消、取消中、参数校验 | 不作为成功或失败动作触发器 |
| 连续结果到达 | 当前动作完成后播放最近一条待处理反馈；对白随该动作开始更新 |
| 鼠标移动 | 双眼虹膜、瞳孔与高光同步偏移，头部小幅转向 |
| 结果动作播放 | 注视平滑回正，让结果动作优先；结束后恢复鼠标注视 |
| 鼠标移出、窗口失焦、触摸输入 | 注视回正；触屏不模拟鼠标注视 |
| 减少动态、静态降级 | 保留结果文字，停止动作与注视；开启减少动态会保留最近待显示的结果文字 |
| 页面隐藏 | 停止当前动作，隐藏期间不播放结果动作 |
| 切换功能、返回或换项目 | 清理过期演示与动作，不在新页面补播旧反馈 |

## 实现约束

复用 assets/OpenGMS_A.glb 的骨骼和动画，不修改 GLB 或 Blender 源文件。RobotInteraction 把 Idle 分为身体、头颈、右臂三个不重叠的轨道集合；Yes 只覆盖头颈，Wave 只覆盖右臂。挥手期间暂停头颈 Idle，确保 No 不摇头。现有骨骼名称由实际 GLTFLoader 解析后取得，区分 Head 骨骼和同名网格。

结果动作使用 LoopOnce；进入混合180ms，返回混合280ms。手臂动作期间工作页相机从22°暂时放宽至桌面29°／手机38°，取景中心向手臂侧移0.23个世界单位；结束后回到原近景。手机陪伴层级为3，位于工作内容背景（层级2）之上，仍不拦截鼠标。

注视头部最大附加偏航±8°、俯仰±5°；眼部细节在本地镜片平面内最多偏移 X±0.07、Y±0.045，Z不变，指数跟随时间常数160ms。每次更新先恢复前一次叠加前的骨骼四元数，再求本帧姿态，防止累积旋转。静止工作页在注视稳定后不继续重绘。

## 后续正式接入

原型通过 `D01.observeTask({id, state})` 演示状态接入契约。正式前端应在自己的任务查询/订阅边界调用 TaskFeedback.observe，先静默录入初始快照，再传入该任务后续状态。一个任务 ID 表示一次尝试；重试使用新 ID。已有终态后的重复或倒退状态不重播，缓存最多512个任务状态。

真实应用的任务列表、日志和结果图层仍由其数据层负责更新。不要把“检查分析参数”或 HTTP 请求发送成功接成 succeeded；只有作业本身返回终态才触发。原型没有实时任务订阅，也没有新增业务写接口。未来替换角色资产时重新校验骨骼、眼部节点和 Wave 动作可见性。

采用本地 vendored Three.js 0.180.0。相关接口参考：[AnimationAction](https://threejs.org/docs/pages/AnimationAction.html)、[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)。
