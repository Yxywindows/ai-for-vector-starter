# 文档与代码关系维护

[AI 入口](README.md) · [业务映射](../business-map.md)

## 来源优先级

用户要求与适用仓库约束决定任务范围；实际代码、配置和测试决定当前实现说明。当前文档提供导航，历史方案解释原始意图。代码和文档冲突时先确认调用链，再修正说明。

功能使用稳定的 `B01` 等标识，定义在业务映射；它们是文档索引，不是应用枚举或数据库 ID。路径链接指向真实文件，精确定位用符号名，避免大段复制代码和易漂移行号。

## 修改联动

| 代码变化 | 必须复核的文档 |
|---|---|
| 页面、入口、状态归属 | frontend、code-map、business-map |
| 路由、请求/响应、错误语义 | api、backend、business-map |
| 数据模型、迁移、文件所有权 | architecture、backend、learning/02 |
| 导入、任务、分析、导出 | business-map、backend、api |
| 图层加载、缓存、渲染 | frontend、architecture、learning/04–08 |
| 事务、取消、编辑保存 | backend、frontend、learning/09 |
| 默认配置、命令或测试依赖 | development、根/模块 README |
| 性能结论 | benchmarks，附新环境、提交和原始测量位置 |

## 更新步骤

1. 用功能 ID 找入口、实现和测试；记录本次影响的契约。
2. 修改实现后更新相应现状说明，保留限制条件。
3. 检查相对链接、文件路径、方法/路由、配置默认值与状态名。
4. 检查有无把计划写成已完成、把独立模块写成已接入、把局部测试写成端到端保证。
5. 审阅 `git diff --check` 和实际 diff；文档变更记录应说明验证范围。

历史设计不反向重写成“当时已完成”。旧计划顶部统一标注历史状态，并从当前目录引导到正确现状文档。历史性能数据保留原日期和提交，不重新贴成最新成绩。
